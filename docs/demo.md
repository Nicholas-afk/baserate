# Final-release demonstration

[Watch the demo and download the project files](https://nicholas-afk.github.io/baserate/project.html).

The 112-second, 16:9 demo uses the entrant's supplied 58.697-second narration without synthesized words, rearrangement or speech cuts. The source waveform remains unchanged and private. Level gain and a peak limiter are applied to the delivered audio. No music or generated voice is included.

All application pixels come from genuine browser interactions with the final public app. The edit uses cropped screen-state captures, holds and hard cuts, rather than a continuous screen recording. There is no rebuilt interface or invented cursor. The walkthrough's estimates (90%, 80%, 50%) are staged demonstration inputs, not learner-study observations. All three cases were actually completed and the notebook export control was used.

## Narration qualifications

- **“29 of 30 separate synthetic examples”** means the raw result on the unchanged same-project synthetic holdout. The splits contain no exact duplicate sentences but share authorship, task and familiar claim patterns. On screen: 28 accepted labels, 27 correct. These are development checks, not an independent benchmark or proof of learning.
- **Coach feedback** proposes a review topic. It can misread a correct explanation. The factual check verifies only the selected option; it does not verify the explanation, diagnose a misconception or grade competence.
- **“The words stay in the browser”** describes the application's local inference and tab memory. Static app/model/media requests still contact GitHub Pages. A connected browser assistant has separate data handling.
- **Educational value** is an intended use. No learner study, clinical validation or measured health benefit has been completed.
- **AI assistance** is extensive and disclosed. Automatic local transcription has an uncertain/clipped word near 55 seconds; the edit does not reconstruct it. The complete disclosure appears on screen. Short editorial annotations are not presented as verbatim captions.

## Format and submission status

The [official overview](https://univabio.devpost.com/) requests an interactive prototype, a demo explaining purpose/features and users interacting, a one-page description and repository/code PDF. No numeric video-duration or encoding limit was found in the current overview or [rules](https://univabio.devpost.com/rules) when checked on 6 October 2026. This observation is not organizer clarification of the conflicting deadlines; planning retains the earlier cutoff.

[Devpost's video guidance](https://help.devpost.com/article/85-uploading-a-demo-video) accepts YouTube, Vimeo or Youku for its embedded video field. The direct GitHub Pages MP4 is publicly accessible but is not a supported embed URL. The existing YouTube account is at Create channel, which accepts Terms. That pending personal acceptance is the exact blocker to an accepted embedded upload; no channel or duplicate account has been created and no unsupported URL is substituted into the field.

The one-page PDF, complete source PDF, runnable ZIP, updated screenshots and thumbnail accompany the demo. The video poster remains 16:9; a separate [1200-by-800 Devpost cover](../dist/media/devpost-thumbnail.png) uses the recommended 3:2 ratio and keeps the title readable. Its [editable SVG source](assets/devpost-cover.svg) uses the existing project typography and palette. The raw voice file and private video-working directory are excluded from the repository. The original app model, dataset and classifications are unchanged; the five application test suites and deterministic audit were rerun for this materials refresh.
